00如何使用本文件

這份文件是給 AI 模型用的需求規格，目的是讓不同 AI（Claude / GPT / Gemini / Grok / 其他）依據同一份標準產出 HTML 簡報，方便你比較哪一個模型的成果最符合需求。

► 操作流程
  1. 讀完本文件，確認規格與你期待一致（必要時調整）
  2. 跳到 §12 給其他 AI 的 Prompt，整段複製
  3. 貼到要測試的 AI 模型對話框
  4. 收到產出後，用 §13 評估標準 打分數
  5. 比較多個模型的結果
► 為什麼要這樣測試

不同 AI 模型對「結構性指令」的理解能力差異很大。同樣一份規格，有的模型只做出表面樣式、有的會做出真正符合敘事邏輯的成果。標準化的 brief 是公平比較的前提。

02核心定位

這門課不是：

  • ❌ AI 工具教學（ChatGPT / Claude 怎麼用）
  • ❌ Prompt 工程課
  • ❌ Obsidian 操作教學

這門課是：

  • ✅ 個人知識管理 × AI 時代的身分選擇
  • ✅ 教學員「把 AI 對話、學習、經驗變成可累積的資產」
  • ✅ 用 Markdown × Obsidian × LLM 三層架構讓知識複利
「AI 不會取代你，但會取代不會用 AI 累積自己的人。」

03目標聽眾

首場：大一學生

  • 已經有 AI 使用經驗，但停留在「問答」層次
  • 還沒建立筆記習慣，知識散落各處
  • 對未來有焦慮但不知如何下手
  • 對「複利」概念能接受但缺乏具體感受

通用目標（未來其他場域）

  • 社會人士 / 上班族
  • 進修部、空大、社區大學成人學員
  • 自由工作者、創業者、內容創作者
► 共通特徵

無論場域，目標都是：「已經在用 AI、但沒在累積」的人。這個族群才是這門課的真正受眾。

04教學目標

完成課程後，學員能夠：

  1. 理解 AI 真正的價值不在工具本身，而在於是否能與個人知識系統結合
  2. 掌握「載體（Markdown）× 容器（Obsidian）× 串接（LLM）」三層架構的概念
  3. 說出為什麼 Markdown 是知識資產的最佳格式
  4. 理解 Obsidian 跟其他知識管理工具的核心差異
  5. 知道 Claude Desktop + MCP 如何讓 AI 直接讀取個人知識庫
  6. 建立「知識複利」的長期觀念，把每一次學習當成資產累積
  7. 有明確的行動清單：第一週、第一個月、第三個月該做什麼

05敘事主軸與金句

主軸金句（從頭講到尾）

「AI 不會取代你，
但 AI 會取代不會用 AI 累積自己的人。」

敘事弧線（從第一張到最後一張）

  1. 共鳴：你以前以為 AI 賽局是看誰最強、prompt 最強
  2. 翻轉：發現所有 AI 都在進化，沒有冠軍，真正的問題是「你」
  3. 診斷：你的學習沒有「容器」
  4. 方案：第二大腦的三層架構
  5. 實證：講師的真實 vault + LIVE DEMO
  6. 路線圖：一週、一月、三月分階段行動
  7. 身分選擇：五年後你想當哪一種人

輔助金句（散落在不同模組）

  • 「沒有哪個 AI 最厲害。所有 AI 都在以週為單位進化，今天的冠軍下個月就過時。」
  • 「我的大腦有跟著 AI 一起進化嗎？」
  • 「問題不是你不夠努力，是你的學習沒有『容器』。」
  • 「AI 是頂級主廚，但你冰箱要有食材。沒有素材庫，AI 只能煮泡麵。」
  • 「一次寫，永遠用，到處用。」
  • 「書讀完不是結束，是新連結的開始。」
  • 「AI 變成『認識你的同事』，不是『網路客服』。」
  • 「差距不在天份，在系統。」

06模組架構（11 模組）

整個簡報由 11 個模組構成，每個模組有 1–5 張 slide。模組之間用 section-divider 章節隔頁。

模組標籤定義：CORE 不可省略｜DEMO 現場操作｜OPTIONAL 可選跳過

M00一個轉念｜開場故事
CORE
用講師自身的「AI 賽局誤解 → 轉念」故事，建立全場最重要的認知翻轉。
MUST INCLUDE
  • 三個常見 AI 誤解（哪個最聰明 / 哪個 prompt 最強 / 怎麼問才對）
  • 金句：「沒有哪個 AI 最厲害」
  • 金句：「我的大腦有跟著 AI 一起進化嗎？」
  • 講師「於是我開始建第二大腦」的轉折
M01我是誰｜講師背景
CORE
建立講師可信度——不是一般 AI 老師，是真實的業界實踐者。
MUST INCLUDE
  • 講師身份：期貨營業員 + 程式開發者
  • 差異化故事：別的營業員接電話，他寫程式幫客戶實現策略
  • 痛點故事：「以前每個新專案都要從零開始」
  • 對比數字：3 天 → 30 分鐘（建知識庫前 vs 後）
M02你的痛｜聽眾現狀
CORE
把講師的痛轉接到聽眾自己身上，激起情緒共鳴。
MUST INCLUDE
  • 三到四個誠實提問（你上週跟 AI 講的話還找得到嗎？等）
  • 診斷句：「問題不是你不夠努力，是你的學習沒有『容器』」
  • 對比譬喻：把 AI 當外送員 vs 廚房助手
M03第二大腦三層架構
CORE
建立全場最關鍵的概念框架，後面所有模組都會回扣到這三層。
MUST INCLUDE
  • 歷史脈絡：Zettelkasten (1940s) → PARA (2000s) → LLM-Native (2024+)
  • 三層架構表：① 載體 Markdown ② 容器 Obsidian ③ 串接 Claude+MCP
  • 強調「2024+ 的關鍵差別：AI 能直接調用你的知識庫」
M04為什麼是 Markdown
CORE
解釋為什麼選擇純文字 .md 格式，這是整個系統能複利的根本。
MUST INCLUDE
  • VS 對比：封閉格式（Word/Notion/PDF/截圖）vs Markdown
  • Markdown 語法示範（5 個符號就夠）
  • 跨平台跨工具示範（同一份 .md 可用 Obsidian / VS Code / 任何 AI 開）
M05為什麼是 Obsidian
CORE
解釋為什麼不是 Notion / Evernote，建立工具選擇的合理性。
MUST INCLUDE
  • 市場選擇對照（Notion / Evernote / OneNote / Apple Notes / Roam / Logseq）
  • Obsidian 核心優勢：本地檔案、純 MD、免費、graph、plugin 生態
  • 講師實際 vault graph 截圖（檔案位於 assets/my-vault-graph.png）
  • 講師 vault 三大區塊：工作專案 / 書籍課程 / 日常累積
M06LLM × Vault｜Claude Desktop + MCP
CORE DEMO
展示「AI 直接讀你的 vault」這個震撼能力——整場課的高潮點。
MUST INCLUDE
  • 過去 vs 現在的對話對比（AI 從網路答 vs AI 從你的 vault 答）
  • MCP 概念簡述（不講技術細節）
  • 三步驟設定流程（裝 Claude Desktop / 裝 Obsidian / 設定 MCP）
  • LIVE DEMO 區塊：4 步驟現場示範
M07三個真實用法
CORE
用講師真實場景把抽象概念落地，每個用法都有「做法 + 累積效果」對照。
MUST INCLUDE
  • 用法 1：拆解過去寫過的程式（EvoCode、TradeApi 等）
  • 用法 2：讀書不再消失（《遊戲化實戰》、《裸 K 線交易法》等）
  • 用法 3：Daily Note 每日累積
  • 每個用法都有「做法 / 累積效果」兩欄
M08HANDOFF 進階模式
OPTIONAL
給進階學員的彩蛋——時間不夠可跳過。
MUST INCLUDE
  • HANDOFF 筆記範例（Markdown 程式碼區塊）
  • 應用情境：跨對話、跨 AI 工具的記憶交接
M09三階段行動清單
CORE
把「我該怎麼開始」拆成具體可執行的時間階梯。
MUST INCLUDE
  • 第一週：裝工具、建 vault、寫第一篇 daily note
  • 第一個月：建立習慣、裝 plugin、每週整理一份檔案
  • 第三個月：感受複利、嘗試 MCP 串接
M10身分選擇｜收尾
CORE
最後的情緒鉤子——把行動上升到「你想當哪一種人」的高度。
MUST INCLUDE
  • 五年後對比：A 型（沒累積）vs B 型（有複利）
  • 主軸金句完整呈現（最大字級）
  • 今晚的功課（4 個具體動作）

09視覺與動畫

色彩系統

用途色碼用法
主背景#0a0a0f頁面底色（深黑）
卡片背景#1c1c28card / vs-col / pre
主強調色#7dd3fc 淺藍highlight、accent、title 漸層起點
次強調色#f472b6 洋紅Demo callout、title 漸層終點
警示色#fbbf24 琥珀黃highlight-warning、否定面
成功色#4ade80 翠綠highlight-success、肯定面
危險色#f87171 朱紅VS 對比的「bad」欄

字型

  • 中文與系統字：Noto Sans TC（900 / 700 / 500 / 400）
  • 程式碼與標示：JetBrains Mono（700 / 400）

必要動畫（讓 HTML 跳脫 PPTX 感）

  • 標題漸層位移（持續、6 秒循環）
  • 章節隔頁標題入場（fade-up + cubic-bezier）
  • 大數字彈跳放大（cubic-bezier overshoot）
  • VS 對比左右滑入（左欄左滑、右欄右滑、中央延遲淡入）
  • 三欄卡片階梯式浮起（每欄延遲 0.15s）
  • Demo callout 持續脈衝光暈（吸引注意）
  • 列印模式自動關閉所有動畫
► PRINCIPLE

動畫要「少而精」——目的是區別於 PPTX，不是搶戲。每張 slide 不超過 2 個動效。持續動畫只用在 Demo callout 與標題漸層。

10技術規格

項目規格
框架Reveal.js v5.x，CDN 載入（cdn.jsdelivr.net）
依賴Reveal.js core + notes plugin + markdown plugin + highlight plugin
字型Google Fonts（Noto Sans TC + JetBrains Mono）
theme 基底black.css，再用 custom CSS 覆寫
畫面尺寸1280 × 800（4:3 與 16:9 中間值，投影機相容）
翻頁方式slide 過場、background fade、hash 路由
列印 PDF支援 ?print-pdf 模式
講者備註用 <aside class="notes"> 包裝，按 S 鍵顯示
跨裝置RWD（手機可閱讀但設計以桌機投影為主）

11交付規格

  • 單一 .html 檔，所有 CSS / JS / structure 內嵌（除字型與 Reveal.js 用 CDN）
  • 圖片資產放在同層 assets/ 資料夾，用相對路徑引用
  • 所有模組之間用清楚的 HTML 註解分隔（<!-- MODULE XX -->），方便後續維護
  • 每個模組的 slide 都標 <div class="module-label"> 在左上角，讓講者隨時知道現在在哪
  • 不依賴本機檔案，雙擊 HTML 就能在 Chrome / Edge / Safari 開啟並運作
  • 檔名建議：index.html（如要上傳到網站根目錄）或具描述性的英文檔名（避免 URL 編碼問題）

13評估標準

用以下 10 個維度為每個 AI 的產出打分，每項 1–5 分，總分 50 分。

#評分維度什麼是 5 分
1結構完整度11 個模組全部齊全，順序正確，模組之間有 section divider
2敘事連貫性從共鳴 → 翻轉 → 診斷 → 方案 → 實證 → 行動 → 身分，邏輯流暢不跳針
3主軸金句呈現核心金句出現至少 2 次（開場 + 收尾），且最大字級呈現
4講師故事真實感「3 天 → 30 分鐘」具體對比、講師身份明確、真實 vault 內容（EvoCode 等）有用上
